1JWT কী ও কীভাবে কাজ করে

JWT = তিনটি অংশ header.payload.signature। payload-এ ইউজারের তথ্য থাকে, signature দিয়ে সার্ভার বোঝে টোকেনটা বদলানো হয়নি।

headerঅ্যালগরিদম (HS256)
payloaduserId, role, exp (মেয়াদ) — এনকোড করা, এনক্রিপ্ট নয়
signatureSECRET দিয়ে বানানো সিল; payload বদলালে মিলবে না

🧪 নিজে ডিকোড করে দেখো

⚠️ ডিকোড করতে কারো secret লাগে না, তাই payload-এ পাসওয়ার্ড বা গোপন তথ্য কখনো রেখো না। যাচাই (verify) শুধু SECRET দিয়ে সম্ভব।
💡 এই টোকেনের signature ডেমো, তাই এটা কোনো সার্ভারে যাচাই হবে না।

2আমাদের প্রজেক্টে JWT-র ব্যবহার

প্রবাহ: লগইন → সার্ভার JWT বানায় → httpOnly কুকিতে বসে → প্রতি রিকোয়েস্টে ব্রাউজার নিজেই কুকি পাঠায় → সার্ভার verify করে।

session.ts (অংশ)
const token = await new SignJWT({ userId })
  .setProtectedHeader({ alg: "HS256" })
  .setExpirationTime("7d")
  .sign(key);
cookies().set("session", token, { httpOnly: true, secure: true, sameSite: "lax", path: "/" });

🔍 লাইনে লাইনে ব্যাখ্যা — কেন এটা ব্যবহার হলো

SignJWT({ userId })payload-এ শুধু ID; বাকি তথ্য দরকারে DB থেকে আনো
setExpirationTime("7d")টোকেন চুরি হলেও চিরকাল চলবে না
.sign(key)SECRET দিয়ে সিল, এটাই জালিয়াতি ঠেকায়
httpOnlyJavaScript কুকি পড়তে পারে না, XSS থেকে সুরক্ষা
secureশুধু HTTPS-এ কুকি যায়
sameSite: "lax"অন্য সাইট থেকে আসা POST-এ কুকি যায় না, CSRF কমে

3Role-based Access (Admin/User)

ধাপ: স্কিমায় role → টোকেনে role → গার্ড ফাংশন → পেজ ও Server Action দুই জায়গায় চেক।

prisma/schema.prisma
enum Role { USER ADMIN }
model User {
  // ...আগের ফিল্ডগুলো
  role Role @default(USER)
}
src/auth.ts (callbacks)
callbacks: {
  jwt({ token, user }) {
    if (user) { token.id = user.id; token.role = user.role; }
    return token;
  },
  session({ session, token }) {
    session.user.id = token.id as string;
    session.user.role = token.role as "USER" | "ADMIN";
    return session;
  },
}
src/lib/guard.ts
import { auth } from "@/auth";
import { redirect } from "next/navigation";

export async function requireRole(role: "USER" | "ADMIN") {
  const s = await auth();
  if (!s?.user) redirect("/");
  if (s.user.role !== role) redirect("/forbidden");
  return s;
}
src/app/admin/actions.ts
"use server";
import { requireRole } from "@/lib/guard";
import { prisma } from "@/lib/prisma";

export async function deleteUser(id: string) {
  await requireRole("ADMIN");           // পেজ লুকানো যথেষ্ট নয়
  await prisma.user.delete({ where: { id } });
}
src/next-auth.d.ts
declare module "next-auth" {
  interface User { role?: "USER" | "ADMIN" }
  interface Session { user: { id: string; role: "USER" | "ADMIN" } & import("next-auth").DefaultSession["user"] }
}

🔍 লাইনে লাইনে ব্যাখ্যা — কেন এটা ব্যবহার হলো

enum Role + @default(USER)নতুন যে-ই আসুক, সবচেয়ে কম ক্ষমতায় শুরু (least privilege)
jwt callback: if (user)user শুধু লগইনের মুহূর্তে থাকে; তখন role টোকেনে তুলে রাখা হয়
session callbackটোকেনের তথ্য সেশনে এনে সার্ভার কম্পোনেন্টে auth() দিয়ে পড়া যায়
requireRole()চেক এক জায়গায় লিখে সব পেজ ও action-এ পুনর্ব্যবহার
Action-এও requireRoleServer Action আসলে পাবলিক endpoint; ব্রাউজার থেকে সরাসরি ডাকা যায়

🖥️ আউটপুট কেমন দেখাবে

/admin
ADMIN mugdho@example.com ➜ ইউজার লিস্ট + [ডিলিট] বাটন

⚠️ JWT সেশনে role টোকেনে আটকে থাকে। ADMIN থেকে USER করলেও ইউজার লগআউট না করা পর্যন্ত পুরোনো role চলবে। সংবেদনশীল কাজে DB থেকে role আবার পড়ো।

4সিকিউরিটি বাড়ানোর উপায়

সার্ভারে যাচাইক্লায়েন্টের সব ইনপুট (ফর্ম, params) সার্ভারে যাচাই করো; zod লাইব্রেরি ভালো
Role ক্লায়েন্টে ভরসা নয়বাটন লুকানো UI-র সুবিধা; আসল গার্ড requireRole
ছোট মেয়াদJWT ১৫ মিনিট–১ দিন; দীর্ঘ লগইনে refresh টোকেন
কুকি ফ্ল্যাগhttpOnly, secure, sameSite সবসময়
SECRETকমপক্ষে ৩২ অক্ষর, কোডে নয়, .env-এ; ফাঁস হলে বদলাও (সব সেশন বাতিল)
Rate limitলগইনে বারবার ভুল চেষ্টা আটকাতে (যেমন Upstash Ratelimit)
পাসওয়ার্ডbcrypt/argon2 দিয়ে hash, cost ১০+
Error বার্তা"ইমেইল বা পাসওয়ার্ড ভুল" একই বার্তা; কোনটা ভুল তা বলো না
